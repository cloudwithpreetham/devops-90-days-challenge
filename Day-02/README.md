Day 2 builds on Day 1 by zooming into the **Software Development Life Cycle (SDLC)** — the standard process every organization, from startups to companies like Amazon or Flipkart, follows to design, build, and ship software — and shows exactly where DevOps practices plug in to make that process faster and more reliable.

---

## What is SDLC?

The SDLC is a structured, repeatable process software teams follow to take an idea from concept to a working product in the hands of users. At its core it boils down to three fundamentals: **design, develop, and test** — but in practice it's broken into more granular phases so each part of the process can be planned, owned, and improved independently.

The end goal of SDLC is always the same: deliver a **high-quality product** that meets customer expectations, on time and with minimal defects.

---

## Phases of SDLC

Using a hypothetical e-commerce platform (adding a new "kids' clothing" section) as a running example, the SDLC breaks down into:

| #   | Phase                       | What Happens                                                                                                                                   |
| --- | --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Planning**                | Gather requirements/ideas and validate demand before committing engineering effort                                                             |
| 2   | **Defining & Requirements** | Document exact specifications — e.g. a Software Requirements Specification (SRS)                                                               |
| 3   | **Designing**               | Produce a High-Level Design (HLD) for architecture/scalability and a Low-Level Design (LLD) for detailed components, databases, and tech stack |
| 4   | **Building**                | Developers write the actual code based on the design                                                                                           |
| 5   | **Testing**                 | Validate the product against functional and quality expectations before release                                                                |
| 6   | **Deployment**              | Ship the tested product to the live environment for end users                                                                                  |
| 7   | **Maintenance & Updates**   | Monitor, fix, and iterate — the cycle repeats for every new feature or fix                                                                     |

SDLC is **cyclical**, not linear — once a product is live, the same phases repeat for the next round of features or improvements.

---

## Where DevOps Fits In

As a DevOps engineer, the highest-leverage phases to focus on are:

- **Building** — automating code builds so they're consistent and repeatable
- **Testing** — setting up CI pipelines to run automated tests and surface issues early
- **Deployment** — automating releases for smooth, low-downtime delivery

While planning, requirements, and design are typically owned by product/engineering leads, understanding them still matters — every automation decision downstream is shaped by what gets decided upstream.

---

## Key Takeaways

- SDLC gives every software team a shared, repeatable process instead of ad-hoc delivery
- The seven phases move from an idea to a live feature and then loop back for the next iteration
- DevOps doesn't replace the SDLC — it **automates and accelerates** the build, test, and deployment phases within it
- Understanding the full SDLC — not just the phases DevOps touches — makes for a stronger, more context-aware DevOps engineer
